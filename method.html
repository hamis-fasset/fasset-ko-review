How I built a production localization lab—not a translation spreadsheet

I designed and operated an agent-assisted system that turned fragmented app copy, source code, Android captures and Figma designs into a reviewable Korean product experience and an engineering-ready release bundle.

The product problem

The input was not one clean source file. It was a 2,499-key copy pack, a later source-code audit, runtime fragments, duplicated values, placeholders, hardcoded UI text, Figma-only redesign copy and partial emulator coverage. A normal translation workflow would hide those gaps until implementation. I made the gaps visible and reviewable first.

AI agents were a delivery system, not a novelty

Parallel specialist work

I decomposed the work into bounded roles: Korean fintech conventions, translation workflow research, ten copy batches, source-route coverage, deployment checks, UX review and repeated visual QA. Shared briefs and machine-readable outputs let agents work concurrently without inventing their own standards.

Human-owned decisions

I kept product judgement centralized: retail versus exchange vocabulary, product/legal register, what stays English, which designs supersede the current app, acceptable preview limitations, and what evidence was strong enough to claim coverage.

Critique loops

The renderer itself became the QA surface. Browser automation exported exactly what the reviewer saw; agents inspected paired English/Korean renders and returned structured findings. Fixes were regenerated and reviewed again instead of being accepted from a first pass.

Evidence over theatre

The system distinguishes pictured states, code routes and unmapped copy. It does not label an uncaptured route as visually verified. This matters: AI speed is useful only when provenance, uncertainty and acceptance criteria survive the process.

What the scripts actually do

Assembly and language QA

  • Propagate duplicate translations safely.
  • Verify every placeholder and newline.
  • Flag particles attached to unknown Korean placeholder values.
  • Detect register drift, banned vocabulary and untranslated copy.

Visual reconstruction

  • OCR the exact English text geometry.
  • Inpaint glyph pixels without flattening gradients or damaging icons.
  • Render editable Korean as positioned HTML.
  • Measure overflow against the actual available box.

Coverage intelligence

  • Trace registered routes to source components.
  • Resolve static localization keys from code.
  • Separate pictured coverage from code-only evidence.
  • Retain unmatched copy instead of silently dropping it.

Release handoff

  • Autosave reviewer state server-side.
  • Export a deterministic review JSON.
  • Apply edits across app, hardcoded and redesign copy.
  • Regenerate references for engineering validation.
The PM work was not “use AI to translate Korean.” It was designing the operating system that made thousands of AI-assisted decisions inspectable, editable and shippable.

Coverage without false confidence

I modeled coverage at three separate layers: source-code inventory, pictured product states, and individual copy strings. Each visual claim is traceable to an Android capture or supplied design; each editable string keeps its source and provenance. That prevents route registrations, reusable components and actual customer screens from being counted as though they were the same thing—and makes the next automation target measurable.

This lab demonstrates an AI-native PM approach: frame the system, encode quality, orchestrate specialist agents, preserve evidence, build the reviewer experience, and leave engineering with deterministic release artifacts.
